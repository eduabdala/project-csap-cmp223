# analysis — Reproducible pipeline (Snakemake)

Automates collection and analysis, following the methodology flowchart
(`.kiro/specs/cmp223/draft.md`). Turns the factor matrix into statistically
processed data.

## Flow

```
config.yaml  ->  build (avr-gcc)  ->  flash (avrdude/UPDI)  ->  collect (scope + LA)
             ->  parse (E=INT V*i dt) ->  aggregate (mean, 95% CI) ->  figures
```

Factors: **algorithm x variant x clock x optimization x operation**. There are
6 binaries (3 algorithms x {ref, asm}); each is built, flashed and measured
separately, for every clock and optimization combination.

## Files

| File | Role | Status |
|------|------|--------|
| `config.yaml`  | Factor matrix and DoE parameters | ready |
| `design.py`    | Builds the factor matrix with pyDOE3 -> `design.csv` | **working / tested** |
| `Snakefile`    | Rule orchestration | skeleton (bench rules = TODO) |

| `figures.py`   | Trade-off plot with error bars | working (needs data) |

## Design of experiments (pyDOE3)

The factor matrix is generated by `design.py` using
[pyDOE3](https://pypi.org/project/pyDOE3/), instead of a manual cartesian
product. This makes the design a named, citable method and lets it be swapped
for a fractional design if the full matrix is too long for the bench.

```bash
python design.py --config config.yaml --print          # preview the combinations
python design.py --config config.yaml --out data/processed/design.csv
snakemake -j1 data/processed/design.csv                 # same, via the `design` rule
```

Config key `design: full` (default) uses `fullfact`; `design: fracfact` with a
`fraction_generator` string uses a 2-level fractional factorial. The Snakefile
builds its `COMBOS` from the same `design.py` logic, so the plan and the runs
never drift apart.

> pyDOE3 is not yet in nixpkgs; `flake.nix` builds it inline from PyPI. The
> `hash` there is a placeholder — fill it in with `nix-prefetch-url` (see the
> comment in `flake.nix`) before the first `nix develop`.

## Usage

```bash
nix develop                 # brings snakemake + scientific python
cd src/analysis
snakemake -n -j1            # dry-run: inspect the DAG
snakemake -j1 all           # full pipeline (needs the bench for flash/collect)
```

  `sigrok-cli` for the logic analyzer. It currently writes an empty CSV
  (placeholder).
- Calibration: create `calib.yaml` with the **measured** shunt value, instead

can validate the statistics with synthetic CSVs before having the hardware.
